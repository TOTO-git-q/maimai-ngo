# rig3.json — PartnerLive2D's own model format (no moc3, no Cubism Editor)

A model3.json whose `FileReferences.Moc` ends in `.rig3.json` is loaded by `RigModel`
(our own evaluator) instead of Live2DCubismCore. Everything else in model3.json
(Textures, Physics, Motions, Expressions, Groups, HitAreas) is unchanged, and the
model exposes the same API as a moc3 model (parameters, parts, drawables), so motions,
physics, expressions, breath, look, eye blink, the tuning page and the MCP all work as is.

The format is Cubism-shaped (parameters, parts, warp/rotation deformers, art meshes
with keyforms) but deliberately simpler; it is generated by scripts, not by hand.
**Two implementations must agree**: C# `src/Core/RigModel.cs` and the Python reference
`rigkit/rig_eval.py` (ngo-live2d-partner). All rules below are normative.

## File

```jsonc
{
  "Version": 1,
  "Canvas": { "Width": 1122, "Height": 1402, "PixelsPerUnit": 1122, "OriginX": 561, "OriginY": 701 },
  "Parameters": [ { "Id": "ParamAngleX", "Min": -30, "Max": 30, "Default": 0 } ],
  "Parts": [ { "Id": "Part_Ame", "Parent": null, "Opacity": 1 } ],
  "Deformers": [
    { "Id": "W_AmeBody", "Type": "Warp", "Parent": null,
      "Rect": [x, y, w, h], "Rows": 3, "Cols": 3,
      "Bindings": [ { "Parameter": "ParamBreath", "Keys": [0, 1] } ],
      "Keyforms": [ { "Points": [x0, y0, x1, y1, ...], "Opacity": 1 }, ... ] },
    { "Id": "R_AmeHead", "Type": "Rotation", "Parent": "W_AmeBody", "Origin": [x, y],
      "Bindings": [ { "Parameter": "ParamAngleZ", "Keys": [-30, 0, 30] } ],
      "Keyforms": [ { "Angle": -8, "X": 0, "Y": 0, "Scale": 1, "Opacity": 1 }, ... ] }
  ],
  "Meshes": [
    { "Id": "Ame_Face", "Part": "Part_Ame", "Parent": "W_AmeFace", "Texture": 0,
      "DrawOrder": 500, "Blend": "Normal", "Masks": [], "InvertMask": false,
      "Vertices": [x, y, ...], "Uvs": [u, v, ...], "Indices": [i0, i1, i2, ...],
      "Bindings": [ ... ],
      "Keyforms": [ { "Offsets": [dx, dy, ...], "Opacity": 1, "DrawOrder": 500 }, ... ] }
  ]
}
```

- All geometry is in **canvas pixels, y down** (the same pixel grid as the source PSD).
- `Parent` / `Part` refer to ids; `null` or missing = root. Arrays are emitted in an order where
  every parent appears before its children (deformers) — implementations may rely on it.
- `Uvs` use the Cubism/Unity convention: `u = px / atlasW`, `v = 1 - py / atlasH`.
- `Indices` are triangles (multiples of 3), each < 65536 vertices per mesh.
- Optional keyform fields default to: `Offsets` = all zero, `Opacity` = 1,
  `DrawOrder` = the mesh's `DrawOrder`, warp `Points` = the rest grid,
  rotation `Angle`=0 `X`=0 `Y`=0 `Scale`=1.
- `Blend`: `Normal` | `Additive` | `Multiplicative`.
- No `Bindings` (or empty) = exactly one keyform (or none → all defaults).

## Keyform interpolation (all object types)

An object with bindings b = 0..B-1 has `Π len(Keys_b)` keyforms. The keyform index for key
indices (i_0..i_{B-1}) is `Σ i_b * stride_b` with `stride_0 = 1`,
`stride_b = stride_{b-1} * len(Keys_{b-1})` (first binding varies fastest).

For each binding with current parameter value v (already clamped to the parameter range):
- `Keys` are strictly increasing. If v <= Keys[0] → (i=0, t=0). If v >= Keys[last] → (i=last-1, t=1)
  (single-key binding → i=0, t=0, no interpolation).
- Otherwise find i with Keys[i] <= v < Keys[i+1], t = (v - Keys[i]) / (Keys[i+1] - Keys[i]).

The result is the multilinear blend of the 2^B corner keyforms, weight of a corner =
Π (t_b if the corner takes i_b+1 else 1 - t_b). Every numeric field (Points, Offsets, Opacity,
Angle, X, Y, Scale, DrawOrder) is blended this way; DrawOrder is then rounded to the nearest int.

## Deformers

Each deformer is a map canvas → canvas. A point is pushed through its parent chain
**innermost first**: `p' = D_root( ... D_parent( D_self(p) ) )` — i.e. apply the mesh's
parent deformer, then that deformer's parent, and so on up to the root. A deformer's own
geometry (`Rect`, `Origin`) is fixed in canvas space and is NOT moved by its parents.

**Warp** — rest grid is the regular grid over `Rect = [x0, y0, w, h]` with `Cols` x `Rows`
cells, i.e. `(Cols+1)*(Rows+1)` points, row-major from the top-left
(point (r, c) at index `r*(Cols+1)+c`, rest position `(x0 + c*w/Cols, y0 + r*h/Rows)`).
Keyform `Points` are the deformed positions of those grid points. For an input p:
```
u = (p.x - x0) / w * Cols ;  v = (p.y - y0) / h * Rows
c = clamp(floor(u), 0, Cols-1) ; r = clamp(floor(v), 0, Rows-1)
fu = u - c ; fv = v - r            // may be < 0 or > 1 outside the rect: linear extrapolation
P00 = Pt(r,c) ; P01 = Pt(r,c+1) ; P10 = Pt(r+1,c) ; P11 = Pt(r+1,c+1)
p' = (1-fu)(1-fv) P00 + fu(1-fv) P01 + (1-fu) fv P10 + fu fv P11
```

**Rotation** — `o = Origin`, keyform (Angle in degrees, X, Y, Scale):
```
d = p - o ; a = Angle * pi / 180
p' = o + (X, Y) + Scale * ( cos(a) d.x - sin(a) d.y ,  sin(a) d.x + cos(a) d.y )
```
(canvas y is down, so positive Angle turns clockwise on screen.)

## Meshes

1. rest vertices + blended `Offsets` → p
2. push p through the parent deformer chain (above)
3. model units for the runtime: `X = (px - OriginX) / PPU`, `Y = (OriginY - py) / PPU` (y up)

Opacity = blended mesh Opacity × Π(blended Opacity of every deformer in its chain)
× Π(opacity of its part and every ancestor part). Part opacity starts at `Opacity` and can be
changed at runtime (SetPartOpacity; used by pose/expressions).

Render order: sort meshes by (blended DrawOrder ascending, then array index); `RenderOrders[i]`
is the rank of mesh i. `Masks` lists mesh ids whose union clips this mesh
(`InvertMask` = draw only outside them).

## Runtime flags (what RigModel reports)

- Constant flags: `BlendAdditive` / `BlendMultiplicative` from `Blend`, `IsInvertedMask`
  from `InvertMask`, `IsDoubleSided` always set.
- Dynamic flags after every `Update()`: `IsVisible` when final opacity > 0, plus
  `VertexPositionsDidChange | OpacityDidChange | DrawOrderDidChange | RenderOrderDidChange`
  (always set; the renderer only uses them to skip work).
- Multiply colour (1,1,1,1), screen colour (0,0,0,1). Texture index from `Texture`.

## Version 2 addition: per-vertex depth and a perspective camera (optional)

A file with `"Version": 2` may add:

```jsonc
"Camera": { "Focal": 2000, "Center": [561, 701],
            "ParamX": "ParamCamX", "ParamY": "ParamCamY", "ParamZ": "ParamCamZ",
            "OrbitPx": 60, "DollyPx": 150 },
"Meshes": [ { ..., "Depths": [z0, z1, ...] } ]      // one value per vertex, canvas px, + = toward the viewer
```

- `Depths` missing = all 0. `Camera` missing = no projection (Version 1 behaviour).
- Camera parameter values are read from the model parameters (clamped as usual); a missing parameter
  id counts as 0.
- Projection is applied **after** the deformer chain and before the pixel → model-unit conversion,
  per vertex, with its own depth z (depths are NOT moved by deformers):

```
x, y, w = value(ParamX), value(ParamY), value(ParamZ)
t  = (x * OrbitPx, y * OrbitPx)          // camera translation parallel to the picture
D  = Focal - w * DollyPx                 // camera distance to the picture plane (w > 0 = push in)
proj(p; t, D) = C + ( (C + t) + (p - (C + t)) * D / (D - z) - C ) * Focal / D
p' = p + proj(p; t, D) - proj(p; (0,0), Focal)
```
  (C = Center). At x = y = w = 0 this is exactly the identity, so the rest pose never changes. Near
  vertices (z > 0) move opposite to the camera translation and grow more when pushing in. If
  `D - z <= 1` for a vertex, clamp `D - z` to 1.
- Draw order, opacity and masks are unchanged by the camera.
