# Skin asset pipeline (resources.assets, bundles, XMLs)

Almost the whole look is written into the game's own files, not done at runtime: a runtime swap
(`ThemeOverride`, `NgoTint`, `NgoBackground`) shows stock art for a moment and costs work per frame, so those hooks
are off unless their file / setting exists. What the mod still does at runtime is listed in architecture.md.

## Where things live

| data | file |
|---|---|
| UI textures, sprites (meshes, rects), Image colours, prefab transforms, materials, particle systems, the 3D menu background | `<PKG>\Sinmai_Data\resources.assets` (+ `resources.assets.resS` for stock pixel data) |
| navi puppets (the result / select "bear"), chara pictures, other per-item art | `<PKG>\Sinmai_Data\StreamingAssets\A000\AssetBundleImages\...\*.ab` (e.g. `navichara\prefab\ui_navichara_00.ab`, chara `ui_chara_<id>.ab`) |
| sort-tab colours, partner / music data | StreamingAssets XMLs (`musicLevel\*\MusicLevel.xml` Color, genre / version / name / rank tables) |
| mod-loaded art | `<ASSETS>\...` (see architecture.md) |

Stock copies and per-step snapshots: `<GAME_ROOT>\backup_ngo_skin\` - `resources.assets` + `.resS` (stock, SHA256 in
`SHA256.txt`), `resources.assets.before-<step>` (one per install round), `*.ab.orig` / `.before-*`, `select_b\`,
`select_c\` (XML originals), `select_layout.ini.before-*`. Restore = copy back with the game stopped.

## Study the stock format first

Redraws that ignored the stock format came back deformed or mis-coloured several times. Before drawing anything:

1. On the screen in question: MCP `test_ui_dump` (sprite, texture, on-screen rect, Image type, tint, path) and
   `test_tree` (hierarchy, canvases, draw order). `tools\ngo_screen_sprites.py` lists them per walk capture.
2. `python tools\ngo_stock_format.py <out> <texture> [...]` -> the untouched stock PNG (from the backup) and
   `FORMAT.md`: size, sprite border (9-slice L,B,R,T), pivot, every Image using it (GameObject, Image type
   Simple / Sliced / Tiled / Filled, serialized tint, preserveAspect) and a guess whether it is a white mask meant to be
   tinted. `ngo_format_groups.py <out> name=regex ...` does groups and dumps atlas sprite rects (digit fonts).
3. Find every copy: `ngo_find_tex.py <name>` (resources.assets, sharedassets, level files, bundles),
   `ngo_tex_refs.py` (materials / sprites using it), `ngo_find_nodes.py`, `ngo_prefab_tree.py`, `ngo_node_tree.py`.
4. Note the roles: base + overlay pairs (e.g. a selected tab = full-colour base + a white silhouette whose alpha the
   game pulses), 9-slice rows that must stay fixed (the tab tray: top 72 rows fixed, 12 stretched), white masks the
   game tints per screen, sprites reused on other screens (SelectorTab / SelectorBG are shared with the character,
   collection and pass screens).
5. Draw at the stock size with the stock structure; preview the way the game draws (tint first, then 9-slice stretch).

Conventions this skin keeps (they carry meaning, not taste): per-difficulty colours stay (BASIC green, ADVANCED
orange/yellow, EXPERT red, MASTER purple, Re:MASTER lavender, UTAGE pink), the red last-seconds timer stays red;
`Null_Selector_ColorBase._colors` is indexed by difficulty, only its category blue (index 7, `#0A87F0`) became NGO
lavender. Song frames are generated by one tool for select, track start and gameplay (`ngo_diff_frames.py`,
`ngo_upe_hud.py`) so they stay identical across screens. The palette comes from the original game's UI: Windose face
`#F7E1FB`, border `#815CDD`, close button `#4D23CF`, JINE pink `#EE98EE`, lavender `#C3A6E3` in place of maimai blue
(ramps in `tools\ngo_ramp.py`, mirrored in `NgoTint.cs`). The art was drawn as pictures first; scripts only cut,
align, recolour and assemble it into the stock formats.

## Patching with UnityPy

```python
import UnityPy
from UnityPy.helpers.TypeTreeGenerator import TypeTreeGenerator
env = UnityPy.load(r"<PKG>\Sinmai_Data\resources.assets")      # the GAME's copy, not a backup
gen = TypeTreeGenerator("2018.4.7f1")
gen.load_local_dll_folder(r"<PKG>\Sinmai_Data\Managed")          # MonoBehaviour typetrees from the game's DLLs
env.typetree_generator = gen
tree = obj.read_typetree(); ...; obj.save_typetree(tree)        # once per object per run
data = env.file.save()                                          # build ALL output first
assert len(data) > 60 * 1024 * 1024                              # a truncated save is much smaller
open(ASSETS + ".new", "wb").write(data)                         # never write onto the open source
```

Then `powershell -ExecutionPolicy Bypass -File tools\ngo_install_new.ps1` copies `.new` over the original (refuses
while a live Sinmai.exe runs) and deletes `.new`. Rules that cost a round each when broken:

- Read typetrees from the game folder's file: a backup copy elsewhere lacks its external references, so MonoBehaviour
  typetrees cannot be generated.
- One read-modify-save per object per run: UnityPy re-reads an unchanged object from the source, so a second
  read-modify-save of the same object starts from the stock data and drops the first edit.
- UnityPy reads lazily from the original file: build the complete output before opening anything for writing, and
  write `.new` (renaming onto the game file fails from Python; the PowerShell copy works).
- Textures keep name, size and format (`set_image(img, target_format=<stock format>)`); the pixels move from `.resS`
  into `.assets`, so the patched file grows from ~67 MB to ~175 MB. BC7 is encoded with `etcpak` (`compress_bc7`);
  decode BC7 with `texture2ddecoder.decode_bc7` (returns BGRA) - `etcpak.decompress_bc7` fails on this setup.
- Bundles: `NGO_TARGET=<path>.ab python tools\ngo_patch_assets.py ...` saves lz4 to `<path>.ab.new`; move it over.

## The tools by job

| job | tool |
|---|---|
| PNGs named after textures -> resources.assets (or a bundle) | `ngo_patch_assets.py <png dir> <log.csv> [--only a,b]`; size mismatches are skipped; sprites whose new art leaves the stock trimmed rect get their `textureRect` opened to the full rect |
| traced sprite meshes clip redrawn art | `ngo_full_quad.py <sprite> ...` (full-rect quad; skip 9-slice / Sliced sprites, they keep their mesh) |
| Image tints (white masks) | `ngo_tint_map.py tints.json` (`{"<texture>": {"#cur": "#new"}}`, alpha kept, unmatched listed); `ngo_patch_colors.py <textures.txt>` (blue -> violet ramp, green -> pink ramp for all Images of those textures); `ngo_patch_color_fields.py` (selector colour arrays) |
| colours the game sets from code (no serialized field) | runtime `NgoTint` with the texture listed in `<ASSETS>\ngo_tint.txt` |
| stock art that is itself blue / green | `ngo_recolor_stock.py`, `ngo_recolor_blue2.py`, `ngo_recolor_transi.py` -> PNGs for `ngo_patch_assets.py` |
| transforms / scales in prefabs | `ngo_timer_move.py`, `ngo_puppet_scale.py`, `ngo_shadow_align.py`, `ngo_leader_lv_scale.py`, `ngo_partner_row_scale.py`, `ngo_hud_lv_move.py` (absolute from stock values, safe to re-run) |
| pixel font | `ngo_font_data.py` puts the TTF bytes into LiberationSans (Unity 2018 cannot load a TTF from disk); `pixel_font.txt` turns `NgoPixelFont` on; digit atlases `ngo_digits_from_font.py`, level digits `ngo_mlevel_font.py`, `ngo_pixelate.py` |
| title, transitions, entry, passport, cards, rank masks, end flow | `ngo_title.py`, `ngo_transi_install.py`, `ngo_crd_entry.py`, `ngo_partner_cards.py`, `ngo_rank_masks.py` + `ngo_rank_masks_apply.sh`, `ngo_endflow_apply.sh`, ... (docstrings say what each touches) |
| rank flash masks | A white flash/mask must sit where its colour SHOWS: the NGO plus face is pure white, so the SSS+ glints (`UI_RSL_Rank_Plus_White02..04`, one L per inner corner) are lines on the purple outline, never the filled silhouette (that flashed a white blob over the outline and the pink shadow) |
| 3D menu background | `ngo_bg_dump.py` / `ngo_bg_clips.py` / `ngo_bg_mats.py` (study), `ngo_bg_bake.py` (images), `ngo_bg_assets.py` (install, reusing the stock objects), `ngo_bg_motion.py` (particle systems re-tuned for motion); check with `test_renderers` |
| sort-tab colours (XML) | `ngo_select_b_files.py`, `ngo_select_c_files.py`, `ngo_sort_colors_white.py` (back up to `select_b\` / `select_c\` once, never overwrite) |
| dump for review | `ngo_dump_tex.py <out> <name>` (installed vs stock), `ngo_tex_list.py <regex>` |

## Background facts (measured)

- Main (circle) screen: `BG_Sky` is a 3D plane; its material was switched to `Sprites/Default` (built-in,
  `unity_builtin_extra` PathID 10753) with a 1080x1080 RGBA32 texture. The texture shows rotated 180 deg, 1 world
  unit = 1 screen px, and the plane centre sits 410 px above the circle centre (local y -413.15, found with a
  calibration grid).
- The stock Loop animation has no Transform bindings: the stock "floating" comes from shaders and particles, so motion
  without a mod means re-tuning the existing particle systems (`ngo_bg_motion.py`) or the slots the animation drives.
- Sorting: the runtime sorting layer "BackGround" sorts before Default. Changing a sprite's `m_SortingLayer` crashed
  the game on the attract screen; changing a MeshRenderer's sorting layer had no runtime effect. Set the material
  render queue to 2450 instead.
- Top screen: the unused full-strip sprite BG (1078x450) was switched on; sky / five lines off; the 9 note sprites keep
  their animation but show float icons (with full-rect meshes, the stock ones are traced around the notes).

## Replay scripts

The current game files are the source of truth. Replay scripts rebuild a state from a backup:
`tools\ngo_motion_try.sh <out>` restores `resources.assets.before-motion`, then re-applies in order the motion,
blue sweep 2, transitions, title, entry, passport, select tabs / NEXT, area select, tab tray and freedom banner
patches, then runs a skin walk. It does NOT replay the end-flow round (`ngo_endflow_apply.sh`) or the later rounds
(pixel font, digits, cards, credit entry, rank masks ...). When you add a patch that must survive a replay, add it to
the replay script too. The geometry scripts for the tab row and board (`ngo_tabrow_geometry.py`,
`ngo_board_fit.py`) are relative: do not run them again on an already fitted preset. Several replay scripts point at
an art workspace outside the repo on the original machine; other cabinets get the result through the release pack.
